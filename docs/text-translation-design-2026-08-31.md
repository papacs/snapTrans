# 统一快捷键：选中文字原位翻译

## 当前结论与范围

按用户最新反馈，主路径改为“选中文字 → 原有翻译快捷键 Alt+Q → 原位置流式翻译”。无选中文字或无法可靠获取选区时，进入现有截图框选，松开鼠标后立即翻译。不要求用户 Ctrl+C、不新增必记快捷键，也不把独立文本窗口作为主要结果展示。

本版已接入 Windows UI Automation 只读选区、原有翻译快捷键与原位覆盖层。已用自建原生 EDIT 控件和独立 Chrome 测试页面验证选区读取；其他应用仍需兼容性验证，不能据此承诺全应用通用。复制成功收起保持不变，不新增 Alt+E。

## 路由

| 触发时状态 | 行为 |
| --- | --- |
| 有非空选中文字，且可见行位置可靠 | 读取文本与位置，直接原位流式翻译，跳过框选和 OCR |
| 没有选中文字（只有插入光标也算没有） | 原有截图框选；松开即开始 OCR 和翻译 |
| 应用不支持、读取超时、只能取文字但取不到位置 | 简短提示后进入原有截图框选，不增加确认步骤 |
| 密码控件、权限受限的安全界面 | 不读取或绕过保护；保持正常受支持操作的边界 |

只检查当前前台应用内的活动选区，不搜索其他窗口的历史选区，不读取旧剪贴板内容。快捷键触发后先取原窗口句柄、焦点与选区，之后才显示自身覆盖窗口，避免先抢焦点导致选区失效。

保留托盘中明确的“截图翻译/框选翻译”操作，始终进入手动框选，用于选区残留但用户想翻译另一区域的情况。现有 Alt+W 截图不变。

## 原位结果保持一致

- 复用现有流式覆盖层、段落换行、字号拟合、图标保留、完整译文与底部按钮。
- 手动复制译文或译后图片成功后收起；复制失败、自动复制、切换方向和查看全文不收起。源程序内容不被修改。
- 输入改成直接获取的文字。可截取本地背景用于冻结画面、取色与导出，但不将背景交给 OCR 或翻译 API。
- 逐行位置与文字要对应；跨段落、跨列和不连续选区不能简单合成一个大矩形，避免遮住中间未选中的内容。
- 屏幕外文本没有可靠的可见行坐标。第一版对无法完整、安全定位的复杂选区回退框选，不假装精确原位覆盖；不通过滚动原应用获取全文。
- 选中高亮颜色与正文背景要分开处理，避免把蓝色选区误当成正文背景；不向原程序发送 Esc 或清空选区来消除高亮。
- 初版沿用现有冻结背景体验。若以后要求译文跟随原应用滚动，是另一项窗口跟踪工作，不在此设计中承诺。

## Windows 技术依据

使用 UI Automation TextPattern.GetSelection 获取选区，TextRange.GetText 获取文本，GetBoundingRectangles 获取可见行的边界。GetSelection 返回空范围时不能把光标附近的整段文字当成用户选中内容。

官方接口允许应用不支持选区，空范围、屏幕外范围也可能没有矩形。因此可行的是“支持的应用自动原位直译，其他应用截图兜底”，不是承诺所有 Windows 程序通用。

- 选区：https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nf-uiautomationclient-iuiautomationtextpattern-getselection
- 行坐标：https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nf-uiautomationclient-iuiautomationtextrange-getboundingrectangles
- 物理像素与缩放：https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-screenscaling
- 独立 COM MTA 线程：https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-threading

## 实现落点

1. 新增 internal/selection：返回来源 HWND、选中文本、对应行/段范围与物理坐标，以及 none/unsupported/timeout/blocked 状态。UIA 放在独立 COM MTA 工作线程；设读取时限，控制并发，避免慢应用拖住快捷键或无限积累阻塞线程。
2. 新增统一翻译触发入口，供 Alt+Q 调用。显式 TriggerCapture 和托盘 Capture 保留框选语义，符合当前项目约定。
3. 选区位置决定目标显示器，不能沿用只看鼠标所在屏幕的 ActiveDisplay。坐标先扣除屏幕物理原点，再经统一 DPI 映射；覆盖 100%/125%/150%、负坐标显示器和应用跨屏等情况。
4. 将现有 OCR 块布局的数据概念抽象为通用文本区域，包含 source=selection/ocr 与稳定区域 ID。选区来源跳过 OCR；翻译与布局共用事件和取消规则，不伪造 OCR 事件。
5. 共用方向检测、配置、API 流式请求、超时和历史。选区输入使用适合原段落/区域的提示词，不强制把正常段落误作 OCR 断行；区域 ID 不展示给用户。
6. 统一 generation 隔离；切换窗口、开始新请求、关闭结果后，旧读取/令牌/复制回调不能改变当前界面。快捷键重复触发不并发创建多次读取或翻译。

## 性能与隐私

不监听每一次选中文字，不后台监听剪贴板，只在用户触发快捷键时读取。第一版不模拟 Ctrl+C；模拟复制会改动剪贴板，还可能在终端等程序中触发其他操作，而且无法单独解决坐标缺失问题。

现有 RapidOCR 本地运行，因此直接文本输入主要节省识别等待和误识别重试。同等内容与模型的 API 成本预计接近；本地背景截图不增加图片模型输入费用。不承诺未经实测的响应时间或费用下降比例。

## 分阶段验收

先做只读选区与定位验证，再接入现有覆盖层和快捷键。优先验收实际使用的 Chrome/Edge 网页正文、Office、记事本、VS Code 与 PDF 阅读器；它们是测试目标，不代表当前已验证兼容。

关键用例：无选择不误读光标内容；中文/英文/多行与部分词选择；链接和代码；跨段/跨列；选区未全部可见；应用切换、慢 UIA、权限限制；剪贴板不变；新旧请求隔离；多屏 DPI；获取失败仍立即可框选；复制成功收起。

## 本版验证记录

- 前端 133 项测试通过，包含选区自动启动、不触发 OCR、反向翻译与重试、取消后的旧事件隔离、复制成功收起和高亮边缘清理；类型检查及生产构建通过。
- Go 全包测试与 vet 通过；覆盖负坐标显示器、100%/125%/150%/200% 坐标映射、跨屏拒绝、请求过期、迟到选区响应和纯文本 API 请求。
- Windows 原生 EDIT 实测多行、中文、部分首行与空插入光标。独立 Chrome 测试页面实测多段选区、原始颜色、前台焦点读取以及剪贴板未改动；修正 Chrome 在行尾返回前一行范围的问题。
- 用原生读取结果接入浏览器中的真实 Vue 覆盖层，确认原位坐标、段落间距、蓝色高亮边缘清理、复制后收起。测试译文由本地桩提供，没有使用真实 API Key 或产生外部 API 请求。
- Office、VS Code、PDF 阅读器和复杂页面尚未逐一验收；不支持或定位不可靠时仍采用框选。译文保持冻结背景，不跟随源窗口滚动。
- 构建为 build/bin/snapTrans-smart-20260831.exe；旧版程序和本地配置未覆盖。需要先退出托盘中的旧版再运行新版。
- 前端构建会清理 dist，Go 编译需要嵌入该目录，因此必须先完成前端构建，再运行 Go 验证和 Wails 构建，不能并行。

原生测试可通过 SNAPTRANS_NATIVE_SELECTION_TEST=1 启用。浏览器测试素材在 internal/selection/testdata/browser-selection.html；在独立测试浏览器中选中两段正文后，设置 SNAPTRANS_BROWSER_SELECTION_TEST=1 再运行 selection 包测试。额外设置 SNAPTRANS_TEST_ACTIVATE_FIXTURE=1 会短暂激活该测试窗口验证前台读取，并恢复先前窗口。常规 go test 不触碰桌面窗口。
