# 译文原位排版优化（2026-08-31）

## 原因

- 旧实现对整张选区统一判断“正文/控件”。推文底部的数字、图标会把正文也判成居中标签。
- 段落扩宽到选区边缘并共用纵向排布，容易跨越引用卡片和其他列。
- 中文字宽估算偏小；预览与 Canvas 导出的换行规则各自独立。
- 相似译文去重可能误删内容不同的两条列表项；OCR 框包含但未识别出的绿色勾选图标会被遮盖。

## 本轮调整

- 新增 overlay-layout.ts：按局部 OCR 区域分类和合并连续正文行，固定原位坐标、字号和行宽，保留短作者身份行与计数。
- 使用实际字体测量来换行；统一微软雅黑字体，支持编号续行缩进和中文行首标点约束。
- 长译文最多缩小两像素，仍放不下则省略显示并提供“完整译文”，不挤压相邻内容。
- 新增 overlay-painter.ts：屏幕预览与导出共用布局结果；导出不拉伸文字、不增高截图。
- 对 OCR 框左侧的实心彩色标记进行小范围检测，保留绿色勾选图标；没有可用译文的区域继续显示原文。
- 移除跨条目模糊去重和选区实体边框造成的坐标偏移。

## 验证

- 用户提供的 593×314 原图运行本地 RapidOCR，真实识别结果保存于 frontend/src/utils/fixtures/tweet-ocr.json。
- 先建立失败的推文排版回归，再修正实现；最终前端 120 项测试通过。
- npm run build（含 TypeScript 检查）、go test ./...、go vet ./...、git diff --check 通过。
- Playwright 使用实际框选操作、真实 OCR 数据及固定译文，验证预览与复制图片流程，未调用线上翻译 API。
- 导出仍为 593×314；作者头像、引用作者栏、底部操作栏、两个绿色勾选图标的像素均与原图一致。
- 预览：../output/playwright/layout-after.png；导出：../output/playwright/layout-export.png（验证产物，不提交）。

## 打包与边界

- build/bin/snapTrans-layout-20260831.exe 为独立构建，未覆盖或关闭正在使用的 snapTrans.exe。
- 先运行 npm run build，再运行 wails build -s -skipbindings -m -nosyncgomod -o snapTrans-layout-20260831.exe。
- 本轮未改 Wails 接口；复用现有绑定，避免生成绑定时被正在运行程序的单实例提示阻塞。
- 这仍是截图像素与 OCR 几何布局，不拥有网页 DOM；复杂图片背景、OCR 错框及很密集的内容仍有边界。超长译文可通过完整译文查看，复制截图保留当前可见省略状态。
- 此轮未重新进行真实 API 延迟测试或多显示器设备验收；新增测试覆盖局部坐标、独立列、流式布局稳定和导出缩放。
